## 2. 비용 — 근거 수식

**측정값** (`text_cache/` 실측, 2026-07-28):
- 시드 9편 = **343쪽, 1,129,783자**
- 텍스트 토큰 ≈ 1,129,783 ÷ 4 = **282,445**
- PDF 문서 블록은 페이지 오버헤드가 더 붙는다. 보수적으로 페이지당 +250 → **≈ 368,000 토큰**

**단가** (claude-opus-4-8, `obs.py:_RATES`): 입력 $5/1M · 출력 $25/1M
캐시 읽기 = 입력의 0.1배 · **캐시 쓰기(1h TTL) = 입력의 2배** (`papers.document_blocks`가 `ttl="1h"`)

```
콜드(1시간 창의 첫 질문) = 368,000/1M × $5 × 2.0 + 800/1M × $25 = $3.68 + $0.02 = $3.70
웜(같은 창 안 후속)      = 368,000/1M × $5 × 0.1 + 800/1M × $25 = $0.18 + $0.02 = $0.20
```

| 시나리오 | 계산 | 비용 |
|---|---|---|
| 질문 20개 한 세션 | $3.70 + $0.20×19 | **$7.58** |
| 같은 세션, 캐시 없이 | ($1.84 + $0.02) × 20 | $37.22 |
| 사용자 1명 월 8세션 | $7.58 × 8 | **$60.6** |
| 노트북 10명 공유, 월 8세션 | $60.6 × 10 | **$606** |

**캐시가 5배를 절약한다.** 그래서 `_doc_blocks_for`가 명시 선택을 레지스트리 순서 그대로 보내는 것이 (`app.py:152`) 최적화가 아니라 **비용 구조 그 자체다.** 여기를 건드리는 PR은 반드시 캐시 적중률을 같이 측정할 것.

## 3. 선행 의존성 — 순서를 바꾸면 다시 짜야 하는 것

1. **공유·권한(21~24)은 실제 로그인이 선행.** 지금 `owner`는 `ACCOUNTS.resolve(device)`라 로그인이 아니다(`app.py:122`). 복원 코드를 아는 사람은 그 계정의 소스를 본다. 로그인 없이 공유를 만들면 권한 모델을 두 번 쓴다.
2. **스튜디오 산출물(43·45·49)은 비용 구조 결정이 선행.** 산출물 1건이 질문 1건과 같은 코퍼스를 다시 태운다. 상한·과금·모델 등급을 정하기 전에 만들면 기능 하나가 청구서를 지배한다.
3. **노트→소스(38)는 노트북 컨테이너가 선행.** 노트가 어느 노트북에 속하는지 정해지지 않으면 "변환한 소스가 어디에 생기는가"에 답할 수 없다. 지금 노트는 계정 전역 평면 목록이다(`app.py:334`).
4. **Q1의 "대화가 자기 소스를 갖는다"가 Q2 전체의 선행.** 어젯밤 클라이언트(`localStorage.rp_sources_by_conv`)로 절반만 했다. 기기를 바꾸면 안 따라온다.
5. **Drive 동기화(11)는 Google OAuth가 선행.** Q3의 로그인 작업과 묶어라. 따로 하면 OAuth를 두 번 붙인다.

1. **원문 뷰어는 1년 뒤에도 레이아웃이 아니라 텍스트다.** `pypdf` 추출본이라 그림·표·수식 배치가 없다. 진짜 PDF 렌더는 pdf.js가 필요하고, 그건 "빌드 스텝 없는 단일 HTML"이라는 전제를 깬다. **깨려면**: 번들러 도입 → `static/index.html` 1,700줄을 모듈로 쪼개는 작업이 선행(L, 분기 하나). 그럴 가치가 있는지는 사용자가 "그림을 못 본다"고 말한 뒤에 판단하라.

2. **개념 그래프는 1년 뒤에도 공용 논문 것이다.** 내가 올린 PDF는 그래프에 안 들어온다(`corpus.regenerate_graph`가 `shared_papers()`만 쓴다). 사용자별 그래프로 가려면 `graph.json` 단일 파일을 사용자별 저장소로 바꿔야 하고, 그러면 `app.py:61`의 프로세스 전역 `NODES`가 통째로 무너진다. **깨려면**: 그래프를 요청 스코프로 (M~L). Q2 노트북 컨테이너와 같이 하는 게 싸다.

3. **한 프로세스·한 워커를 넘지 못한다.** `SessionStore`가 인메모리이고(`session.py:83`) SQLite 연결이 `check_same_thread=False` 단일 연결이다(`history.py:17`). 워커를 2개로 늘리는 순간 세션이 절반씩 사라진다. **깨려면**: 세션을 Redis로, SQLite를 Postgres로 (M). 동시 사용자 50명을 넘길 때 필요하다 — 그 전에는 하지 마라.

4. **비용 계측이 실키로 검증되지 않은 채 Q1에 들어간다.** `cache_creation_input_tokens` 필드명이 맞는지는 실제 스트림 응답을 받아봐야 안다. Q1 첫 주에 **콘솔 청구액과 대조하는 것**을 완료 판정에 넣어둔 이유다.

5. ~~**동시 편집이 없다.**~~ **2026-07-28 해소** (`988a0ec`) — 레지스트리가 SQLite 테이블이 됐다. 동시 등록 40건 실측: JSON 통파일은 11/40 등록 + 파일 손상, SQLite는 40/40 + 예외 0건. 같은 경로 20건 동시 등록도 행 1개(스키마가 강제). 남은 것은 **한 프로세스 천장**(위 3번)이지 레지스트리가 아니다.

6. **MOCK과 실키의 차이가 완전히는 안 없어진다.** 어젯밤 목이 인용을 문장 중간에 내도록 고쳐 구조적 차이 하나를 줄였지만, 목은 여전히 문서 블록을 읽지 않는다. **소스 선택이 답변 "내용"을 바꾸는지는 실키에서만 확인된다.** 이건 설계상 그렇고, 없애려면 목이 곧 모델이어야 한다.
