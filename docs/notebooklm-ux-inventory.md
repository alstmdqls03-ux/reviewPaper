# NotebookLM UX 인벤토리 → reviewPaper 이식 계획

작성 2026-07-27. 목적: "업로드한 소스 관리 · 세션(노트북) 관리" 계열 UX를 reviewPaper에 이식하기 위한 기능 단위 인벤토리 + 구현 판정 체크리스트.

**조사 방식**: 서브에이전트 3개 병렬(소스패널·노트북목록 / 채팅·인용·노트 / 스튜디오). 1차 출처는 support.google.com·blog.google·workspaceupdates.googleblog.com, 2차는 hands-on 리뷰. 확인 못 한 동작은 추측하지 않고 "확인 불가"로 표기했다.

**명칭 주의**: 2026-07-16부로 제품명이 **Gemini Notebook**으로 바뀌었다(도메인·공유링크·기존 노트북은 그대로 유지). 문서마다 옛 이름이 섞여 있어 이 문서는 "NotebookLM"으로 통일한다. [→ 근거 A]

## 0. reviewPaper 현재 상태 (표의 "대응 여부" 판정 근거)

| 항목 | 현재 |
|---|---|
| 화면 구조 | 단일 `static/index.html`, 탭 5개(대화·그래프·학습·노트·기록)를 `showTab()`이 display 토글 (`index.html:399`). 라우트 없음 |
| 상태 | localStorage 3키(`rp_session`·`rp_conv`·`rp_device`) + JS 전역. 스토어·프레임워크 없음 |
| 소스 저장 | `POST /upload` → `uploads/<파일명>` + `corpus.json`에 `{path,title}` append (`app.py:354`, `corpus.py:38`) |
| 소스 조회 | **API·UI 모두 없음.** 업로드 응답의 `corpus_size` 숫자만 토스트 (`index.html:1012`) |
| 소스 스코프 | 프로세스 전역 1개 코퍼스. user_id·conversation에 안 묶임 |
| 소스 선택 | 없음. `corpus.select_documents()`가 자동 결정(≤5편이면 전부, 초과 시 BM25 상위 5편, `corpus.py:133`) |
| 세션 | 라이브 `session_id`(인메모리·TTL 30분) + 영속 `conversation_id`(SQLite `app.db`) 2겹 |
| 세션 목록·전환 | 기록 탭에 목록·재개·소프트삭제 있음. **현재 대화 표시 없음**, 재개 시 인용·노트버튼 유실 (`index.html:1149`) |

## 3. v1 범위

**한 문장**: 업로드한 소스가 무엇인지 목록으로 보이고, 소스별로 답변 근거에서 뺄 수 있고, 세션을 새로 만들고 전환할 때 지금 어느 세션인지 화면에 보인다.

포함 = 표의 O 5개: **#1 소스 목록 · #3 소스 선택/해제 · #16 세션 목록·전환 · #17 새 세션 생성 · #33 세션 이어보기 표시**.

구현 방향(코드 아님, 판정 기준을 위한 전제):
- `GET /corpus` 추가 → `corpus.load_corpus()`를 `[{title, path}]`로 반환. 소스 탭이 이걸 그린다.
- 선택 상태는 클라이언트에 **전역 1개**로 보관(`localStorage` 키 `rp_sources`). `POST /chat` 바디에 선택된 title 배열을 실어 보내고, 서버는 `_uploaded`를 그 집합으로 걸러 문서 블록을 만든다.
- 답변 시작 시 SSE `{"type":"sources", "titles":[...]}` 1건을 먼저 보내 "이 답변이 사용한 소스"를 화면에 띄운다. — **이게 없으면 MOCK 모드에서 선택 해제를 판정할 수 없다** (아래 실패 경계 3번).
- 헤더에 현재 대화 제목을 표시하고, 기록 목록에서 현재 대화 항목만 활성 표시한다.

### 작은 범위로 다시 자른 것 (2026-07-27 재스코핑)

| 뺀 것 | 이유 |
|---|---|
| 대화별 소스 선택 보존 | 코퍼스가 프로세스 전역 1개인데 대화마다 선택을 저장하면 격리가 있는 척하게 된다. 선택은 전역 1개(`rp_sources`)로 두고, "새 대화" 시점의 키 이관 로직을 통째로 없앤다 |
| "출처 목록 각주에 해제한 소스가 없다" 검증 | MOCK은 `graph.json`에서 캔드 인용을 만들어 실키 없이는 판정 불가(실패 경계 3). "사용한 소스" 줄 하나로 판정을 대체한다 |
| "첫 질문 직후 기록 목록 맨 위에 나타난다" | 이미 그렇게 동작한다(`history.append`의 자동 제목 + `updated_at DESC` 정렬). 구현할 게 없다 |

남은 작업 단위는 4개 커밋: **(A) 소스 목록 · (B) 체크박스+전송 가드 · (C) 선택 전달·서버 필터·사용한 소스 표시 · (D) 현재 대화 표시**.

## 4. 정직한 실패 경계

1. **노트북이라는 컨테이너가 없다.** NotebookLM의 노트북 = 소스 묶음 + 대화. reviewPaper에는 대화만 있고 코퍼스는 프로세스 전역 1개다(`app.py:59`, `corpus.json`). v1의 "소스 선택"은 **내 답변의 근거를 좁히는 것일 뿐, 소유·격리가 아니다** — 다른 사용자가 올린 PDF는 여전히 내 소스 목록에 나타난다. 진짜 격리는 저장소 스키마 변경이 필요하고 v1에 없다.
2. **BM25 인덱스는 전역이다.** `corpus._INDEX`는 코퍼스 전체 페이지로 만들어지는 프로세스 캐시라(`corpus.py:107`), 선택 해제한 문서도 랭킹 계산에는 남는다. v1은 `select_documents`의 결과를 선택 집합으로 한 번 더 거르는 방식이라 **답변 근거에서는 확실히 빠지지만, 어떤 문서를 상위로 뽑을지에는 여전히 영향을 준다.** 코퍼스가 6편을 넘는 지금 실제로 발생하는 차이다.
3. **MOCK 모드에서는 소스 선택이 답변 내용을 바꾸지 못한다.** MOCK은 `_uploaded`가 비어 있고(`app.py:67`), `llm._mock_stream`은 문서 블록을 아예 보지 않고 `graph.json`에서 캔드 인용을 만든다(`llm.py:118`). 따라서 오프라인에서 판정 가능한 것은 **"사용한 소스" 목록과 각주에 해당 논문이 없는가"까지**이고, 실제 근거가 바뀌는지는 실키 모드에서만 확인된다. 체크리스트는 이 한계를 전제로 썼다.
4. **재개된 대화의 인용은 복원되지 않는다.** DB에는 답변 텍스트만 저장되고(`history.py`), 재생은 `addBotPlain()`이라 각주·원문 구절·노트 버튼이 없다. v1은 제목·활성 표시만 고치고 인용 복원은 하지 않는다.
5. **소스 삭제가 없다.** `corpus.json`에는 이미 `papers/03-microscopy-metadata.pdf`와 `uploads/03-microscopy-metadata.pdf`가 같은 논문으로 중복 등록돼 있다(경로가 달라 dedupe 통과). v1 이후에도 **UI에서 지울 수 없고**, 체크 해제로 가릴 수만 있다.
6. **URL이 없다.** 라우팅이 없어 세션 전환이 주소에 남지 않는다. 새로고침하면 마지막 `rp_conv`로 돌아가지만 탭은 항상 대화로 리셋된다.
