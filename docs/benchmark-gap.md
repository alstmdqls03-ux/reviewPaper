# UX 벤치마킹 갭 분석 — NotebookLM을 무엇으로 잘못 읽었나

작성 2026-07-28. 대상 커밋 `60931ee`. 실행 전제: `MOCK_LLM=1`, `corpus.json` 10편, 폭 1440px(소스 레일 300px 승격, 그래프 열 미승격).

**조사 방식**: 새 맥락의 적대적 리뷰(서브에이전트 1개, 입장 = "이 이식은 NotebookLM을 잘못 읽었다. 그 증거를 찾아라"). NotebookLM 동작은 현행 `support.google.com/gemininotebook/*`로 재조사했다 — 인벤토리가 인용한 `.../notebooklm/*` 경로는 리브랜딩 이후 이동했고, 인벤토리 §7의 "도메인은 그대로 유지" 서술과 어긋난다.

**검증 표기**: ✅ = 이 문서 작성자가 코드 실행 또는 브라우저 실측으로 직접 재현함. 📄 = 코드 읽기로만 확인(실행 미확인).

**현재 상태 (2026-08-02)**: 21건 중 **19건 해소**. 남은 2건은 **G5·G21**이고, 둘 다
"실키 없이 판정 불가"라서 미해결이다 — 고칠 방법을 몰라서가 아니라 고쳤는지 확인할
수단이 없어서다. 해소된 항목은 아래 표에서 취소선 + 커밋 해시로 표시했다.

## 2. 가설 판정

### 가설 1 — "인벤토리 49행이 기능 목록이지 사용 흐름이 아니었다" → **검증됨**

루프 `소스를 고르고 → 묻고 → 근거를 확인하고 → 노트에 남긴다`를 코드로 끝까지 따라갔다.

1. **고른다** — `renderSources()` 체크박스 (`index.html:1285-1305`) → `onSourceToggle`이 `rp_sources`에 기록 (`index.html:1307-1313`). **이어진다.**
2. **묻는다** — `send()`가 `sources: selectedIds()` POST (`index.html:714`) → `_pick_sources`가 그 집합으로 문서 블록 (`app.py:125-138`). **이어진다.**
3. **근거를 확인한다** — `citation` → `<sup class="cite">` + 출처 행 → `openViewer` (`index.html:679-695, 650-656`). **이어진다.**
4. **노트에 남긴다** — **여기서 끊긴다.** `saveNote(plain, firstCite, …)`가 넘기는 건 평문과 **첫 인용의 제목 문자열 하나**다 (`index.html:638, 682`). `POST /notes`의 스키마에 인용 배열 자리가 없다 (`app.py:176-179`).
5. **다음 바퀴** — 노트에서 소스로도, 대화로도 돌아가는 경로가 DOM에 없다.

끊기는 지점은 **3→4**(근거가 노트로 안 넘어감)와 **4→1**(노트가 다시 소스가 안 됨) 두 곳이고, **둘 다 인벤토리에서 "이번 주제 밖"으로 행 단위 제외된 항목**이다(#36·#38, §2 표). 루프로 봤다면 두 칸이 비어 있다는 사실이 **하나의 결함**으로 잡혔을 것이다. 행으로 봤기 때문에 각각 "다음 사이클"로 흩어졌다.

### 가설 2 — "체크리스트가 전부 '무엇이 보인다'였고 '무엇이 편하다'는 없었다" → **검증됨**

14항목의 동사는 전부 *나열된다 / 보인다 / 표시된다 / 바뀐다 / 통과한다*다. **"몇 줄을 차지하는가", "한 클릭에 몇 개가 움직이는가", "같은 것이 두 곳에서 같게 보이는가", "다음 화면에 도착하는가"를 묻는 항목은 0개다.**

그 결과 같은 종류의 결함이 위 표에 **9건** 남았다 — G4(소스 줄 116px) · G7(추천칩 소멸) · G8(툴바 3줄) · G9(한 클릭에 두 개 이동) · G10(툴팁 이중) · G11(같은 논문 두 표기) · G15(주입이 안 보임) · G16(복습 링크가 빈 화면으로) · G18(Esc가 모달을 안 닫음).

**가장 나쁜 사례는 G5다.** 체크리스트 6·7("사용한 소스 줄에 A가 나타난다/않는다")은 `used_titles`가 레지스트리에서 만들어지므로 **문서 블록이 0개여도 항상 통과한다** (`app.py:145-146`). 화면에 글자가 나타나는지만 물었기 때문에, **그 글자가 참인지**는 14항목 전체가 한 번도 묻지 않았다. 채점기가 거짓말을 통과시킬 수 있게 설계돼 있었다.

### 가설 3 — "노트북 컨테이너를 안 만들고 '대화 + 전역 소스 선택'으로 우회했다" → **검증됨**

우회는 `index.html:1223-1233`의 전역 키 하나다. 그 우회가 지금 불가능하게 만드는 것:

- **대화가 자기 소스를 못 갖는다.** `conversations` 스키마에 소스 컬럼이 없다 (`history.py:27-30`). 소스 정보는 메시지 단위 `meta.sources`로만 존재한다 (`app.py:262`). "이 대화는 무엇을 근거로 하는가"를 답변 하나를 열어보지 않고는 화면에 띄울 수 없다.
- **대화 전환이 소스를 안 바꾼다.** `resumeConversation`은 `rp_conv`·`rp_session`·로그·제목만 건드린다 (`index.html:1599-1617`). `resetChat`도 `rp_sources`를 남긴다 (`index.html:1554-1563`). → G1·G2의 화면 모순.
- **파생 산출물이 대화를 안 따라간다.** 퀴즈(`index.html:788`), 추천 질문(`index.html:503`), 노트(`app.py:334-341`), 숙련도·그래프(`app.py:315-331, 61-63`)가 전부 계정 전역이다. 대화를 바꿔도 그래프의 흰 노드·노트 목록·퀴즈 출제 범위 중 **어느 것도 화면에서 바뀌지 않는다**.
- **생성 흐름이 없다.** NotebookLM은 "Create new notebook → Upload a source"로 생성과 첫 소스를 한 흐름에 묶는다. 이식본의 ＋는 `localStorage` 2키를 지우는 것이 전부다 (`index.html:1565`).

**인벤토리 §3의 재스코핑이 정확히 반대 결과를 낳았다.** 대화별 선택 보존을 "격리가 있는 척하게 된다"는 이유로 뺐는데, 전역 선택 하나로 두면 화면이 **한 대화 안에서 서로 다른 소스 집합을 동시에 주장**한다. 없는 격리를 있는 척하는 것보다, 있는 척조차 못 하고 모순을 보여주는 쪽이 나쁘다.
